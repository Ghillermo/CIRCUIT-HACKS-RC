# Working locally

How to clone the repository and keep developing, testing and sending firmwares from your computer. Versión en español: [`LOCAL.md`](LOCAL.md).

## 0. I only want the firmware
**Easiest:** open `tools/rc_uploader.html` in Chrome / Edge, pick the official firmware ([Novation download](https://components.novationmusic.com/api/v2/firmwares/168/file)) and the version, and send: it patches in the browser without installing anything. It is generated by `tools/make_rc_uploader.py` (in a full checkout, with the `.bin` files).

With Python:
The public repository (RC branch) contains no Novation code or binaries. To get a `.syx` you need the official **Circuit Tracks 1.2.1 (build 4486)** firmware, the one Components serves, as `.syx` or `.bin`:

```bash
python -m pip install -r tools/requirements.txt
python tools/patch_official.py PATH/TO/OFFICIAL_FIRMWARE.syx --version RC0.5
```

- Checks that the file is the official one (SHA-256 in `stock/SHA256SUMS.txt`) and stores it in `stock/`.
- Generates `re/app.asm` and builds the version.
- Checks that the result has the SHA-256 published in `firmware/<version>/manifest.json`.
- `--list` shows the versions; `--all` builds all of them.
- Nothing needs compiling: the DSP assembly comes from the cache `tools/dsp_asm_cache.json`.
- Send the `.syx` with `tools/ct_uploader.html`.

**Back up the SD card before installing.** If you do not want the mod to write anything to the SD card on its own, use `--version RC0.5S`. The beta (new features not yet tested): `--version BETA5`.

## 1. Requirements
| For | You need |
|---|---|
| Sending a `.syx` to the device | Only Chrome or Edge and `tools/ct_uploader.html`, on any system |
| Building and testing | Linux, macOS or **WSL2** on Windows, with Python 3.10+, git, cmake ≥ 3.20, a C++17 compiler (g++ or clang) and ~1 GB free |

On Windows: do all the building and testing inside WSL2 (Ubuntu). Open the uploader in Windows Chrome (`\\wsl$\Ubuntu\home\<you>\CIRCUIT-HACKS-RC\tools\ct_uploader.html`, or copy the file).

### Windows without WSL2 (virtualisation disabled in the BIOS)
With WinLibs installed (step 1), `python tools/setup_dev.py` does steps 2-6 by itself. What it does:
Tested on Windows 10 with Git Bash and Python 3.14; the builds come out identical and the tests pass.
1. `winget install BrechtSanders.WinLibs.POSIX.UCRT` (g++, cmake and ninja; unpacking takes ~30 min). Put its `mingw64\bin` folder in the PATH of the Git Bash session.
2. `python -m pip install -r tools/requirements.txt`.
3. Clone `ext/circuittracksreverseengineering` and `ext/dsp56300` as in `setup_local.sh`. Apply the memtrace patch with `git apply --ignore-whitespace` (the working tree has CRLF line endings).
4. Two local fixes in `ext/dsp56300` (not versioned):
   - `source/dsp56kBase/threadtools.cpp`: the `__try … __except` block inside `#ifdef _MSC_VER`;
   - `source/dsp56kBase/mmuhelper.cpp`: own function types for `VirtualAlloc2` / `MapViewOfFile3` / `UnmapViewOfFile2`, define the `MEM_*_PLACEHOLDER` missing in MinGW and `isSupported()` = `false`.
5. `cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release` and `cmake --build build --target dsp56kEmu`. Then `g++ -O2 -std=c++17 -static -Isource -Isource/asmjit/src ../../tools/dsptool/dsptool.cpp <the 4 libs> -lpthread -o ../bin/dsptool.exe`. With `-static`, Python runs it without MinGW in the PATH. `tools/dsptool_path.py` looks for `ext/bin/dsptool.exe`; `dsptool.cpp` accepts `/dev/stdin` and writes binary output on Windows too.
6. `python tools/gen_listing.py`; `ctre/` can be a copy of `ext/circuittracksreverseengineering` (in Git Bash `ln -s` copies).
7. `run_tests.sh` needs a `python3`: a script `~/bin/python3` with `exec python "$@"`.
8. Every `Session` / `E` of the tests reserves memory: new scripts call `gc.collect()` before creating another one (otherwise Windows runs out of memory).

## 2. Clone and install
```bash
git clone https://github.com/Ghillermo/CIRCUIT-HACKS-RC.git
cd CIRCUIT-HACKS-RC
python tools/setup_dev.py                   # 10–20 min the first time (or: bash tools/setup_local.sh)
```
`setup_dev.py` downloads every dependency from its original source (list, versions and licences in [`DEPENDENCIAS.md`](DEPENDENCIAS.md)) and creates `ext/`, `stock/` and `re/`, which git ignores. `--check` only reports; `--no-dsptool` skips the DSP emulator; `--official FILE` uses your copy of the official firmware instead of downloading it. On Windows without WSL it also applies `tools/dsptool/dsp56300-mingw.patch` (the fixes of step 4 above) and builds with MinGW:

| What | Where | What for |
|---|---|---|
| `capstone==5.0.7`, `unicorn==2.1.4` (pip) | Python environment | ARM listing and ARM emulation |
| userx14 dumps, commit `d6aec9fc` | `ext/circuittracksreverseengineering` + link `ctre/` | RAM and flash of the running device (emulators) |
| dsp56300, commit `44353be2`, + `tools/dsptool/dsp56kEmu-memtrace.patch` | `ext/dsp56300` | DSP56300 emulator |
| `dsptool` | `ext/bin/dsptool` | assemble, disassemble and run DSP code (found by `tools/dsptool_path.py`; another path: variable `DSPTOOL`) |
| `re/app.asm` | `re/` (ignored) | stock Thumb listing; the builders check instructions against it |

If you prefer a virtual environment: `python3 -m venv .venv && . .venv/bin/activate` before the script.

## 3. Check that everything is fine
```bash
bash tools/run_tests.sh          # ~10 min: every build identical to firmware/*/manifest.json + ARM tests
bash tools/run_tests.sh full     # + exact Master FX DSP, full DSP core and line input
```
If `verify_builds.py` reports `DIFF`, it is almost always another Capstone version (the disassembly text changes). Use exactly `capstone==5.0.7`.

## 4. Workflow of a new patch
1. **Builder:** `tools/build_scNN.py`. Usually it imports the previous one, changes its globals or wraps its `dsp_code` and calls its `build()`. Example: `build_sc17_4.py` = `use_mixer14()` + `use_full_leds()` + `linein2`.
2. **Build:** `python3 tools/build_scNN.py stock/circuittracks-firmware-4486-STOCK.bin -o build/scNN` → `.bin`, `.syx` and `manifest.json` (sha, CRC, labels, listing of the new code).
3. **Test in emulation:**
   - ARM: Unicorn over the running RAM dump. Model: `emu_sc17.py`.
   - DSP: `dsp_session.py`, the full core 0 in `dsptool`. Models: `emu_sc17_core.py`, `emu_masterfx_dsp.py`.
4. **Publish:**
   - copy `build/scNN/*` to `firmware/scNN/` and write `PRUEBA.md` (what changes, use, verification, tests on the device and how to go back);
   - add the SHA-256 of the `.syx` to `KNOWN` in `tools/ct_uploader.html` (the uploader only sends files of that list);
   - add the status row to `README.md` and the technical section to `docs/NOTAS.md`;
   - add the entry to `BUILDS` in `tools/verify_builds.py`.
   - The public repository does not publish `.bin` / `.syx` files (they contain Novation’s firmware): only `manifest.json` and `PRUEBA.md`.
5. **Send:** open `tools/ct_uploader.html` in Chrome → Allow MIDI → Identify → pick the `.syx` → Send → press **Play** on the device when asked.
   - Recovery: if it does not start, power it on holding **Scales + Preset + Note** (bootloader mode) and send the official firmware or the last one that worked.

## 5. Tools
| File | Use |
|---|---|
| `tools/ct_fw.py` | `.syx` ↔ `.bin`, CRC-32/MPEG-2 |
| `tools/thumb.py` | minimal Thumb-2 assembler (`Asm`, labels, `b_w`, `bl`, …) |
| `tools/dsp56.py` | DSP56300 assembler (text → words through `dsptool asm`, cached) |
| `tools/gen_listing.py` | regenerates `re/app.asm` |
| `tools/emu_sc05.py` → `emu_sc08.py` (`E8`, `MGR`) | base of the ARM emulators (memory map, dumps, `call`, `set_p0`) |
| `tools/dsp_session.py` | full core 0: init, tables, parameters, MIDI, N blocks; `WATCH`/`TRACE`/`HIST` |
| `tools/dsp_free_scan.py` | looks for unused DSP X/Y memory |
| `tools/verify_builds.py` | rebuilds everything and compares with the manifests |
| `tools/shi_capture.py` | capture of ARM→DSP writes |
| `dsptool dis f.bin [base]` | DSP disassembler; `dsptool dis` with `op opB` lines on stdin |

## 6. Key ideas before touching anything
Read `CLAUDE.md` (summary) and `docs/NOTAS.md` (detail); both are in Spanish. The essentials:
- Identify views and buttons by their behaviour, never by their number. Example: SC17–SC17.2 hooked button 13 believing it was Mixer, and Mixer is 14.
- The free ARM RAM is under the top of the heap: there are 240 B on the device; plan any new state with care.
- DSP memory: only X/Y:$3339–$3BFF is verified free (see `docs/NOTAS.md` for later zones). Nothing in P:$00–$7F.
- Never call `MARK_DIRTY` (`0x0803BDCC`) or anything that takes the DSP service semaphore from the DSP service tick: it locks the device.
- Before sending: the build passes its tests and the older builds stay identical.
